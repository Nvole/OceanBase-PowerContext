# Qoder：从 AI 编程到可运行的数据库工具

整理日期：2026-10-26  
材料：[课程 850](https://open.oceanbase.com/course/850) · [Qoder 官方解析视频](https://www.oceanbase.com/video/9002461)，约 46 分 13 秒

## 1. 课程主要展示什么

课程以一个连接真实 OceanBase 的数据库管理与 AI 数据对账工作台为示范，讲解如何使用 Qoder 完成调研、环境搭建、架构设计、实现、测试和成果展示，再通过 SDK 形成独立应用。

它值得关注的重点是：如何把模型的理解与规划能力组织成可运行、可验证的数据库产品。

**材料边界**：工作台、对账业务、开发耗时、代码行数及测试数量都是讲者的示范内容，不能直接当作所有参赛团队的统一任务或验收指标。正式作品范围仍需核对题包。

## 2. 核心架构：Agent、Skill、Tool

| 层次 | 视频强调的职责 | 实现时应注意 |
|---|---|---|
| Agent | 理解目标、规划步骤和组织执行。 | 明确它可以请求哪些能力，保留决策与调用上下文。 |
| Skill | 描述某类任务的能力与调用契约。 | 输入、输出、适用范围和错误含义要清楚。 |
| Tool | 真正执行数据库操作。 | 参数检查、权限边界和执行记录落实到代码中。 |

课程还强调统一执行入口：Agent 与 Web 界面应复用核心业务能力，使相同操作接受相同校验。否则，界面已经限制的行为可能从另一条调用路径绕过去。

## 3. 一个可以提前准备的最小原型

以下是基于课程的实现建议，不是指定赛题。

选择一个范围明确的数据库辅助任务，例如“读取两份已知表的数据，按确定的键与金额规则生成对账结果”。第一阶段仅覆盖查询与解释：

```text
用户描述任务 → Agent 识别意图 → 选择对应 Skill
            → Tool 校验并读取真实数据库
            → 确定性规则计算结果 → 解释差异并展示依据
```

先验证数据库连接、字段含义、计算规则和结果可追溯，再增加交互、任务编排或数据写入能力。数据库变更只有在正式规则和产品需求明确需要时再扩展。

## 4. 建议的实现顺序

1. **调研与任务定义**：写清使用者、输入、输出、数据语义和完成标准，避免只描述“智能化”。
2. **准备真实环境**：固定 OceanBase 及开发依赖，使用可重复的建表和样例数据脚本。
3. **先实现 Tool**：绕开模型也能以结构化参数运行，产生可核对结果。
4. **定义 Skill 与接入 Agent**：让模型选择能力和填写参数，错误参数应得到明确反馈。
5. **统一界面与 Agent 路径**：两种入口调用同一业务服务或工具执行层。
6. **验证 SDK 与产品形态**：若最终任务需要独立应用，再完成 SDK 接入、配置、打包及新环境启动。

课程展示了 Web、桌面及 IDE 相关形态。是否需要同时支持所有平台，应以正式题包为准，不应为了复制演示而无条件增加多端工作量。

## 5. 验证比生成代码更关键

可以把验证分成三个层次：

- **工具层**：输入和业务规则确定时，数据库查询、计算和错误处理结果正确。
- **协作层**：Agent 能选择正确 Skill，生成合法参数，解释工具返回的真实结果。
- **产品层**：从启动、连接数据库到完成任务，用户能够完整操作并回看结果。

对账类任务尤其需要先给出确定性参考答案，再比较 Agent 驱动的结果。金额精度、重复键、缺失行、空值和关联关系不应只交给模型凭自然语言判断。

## 6. 建议自测与演示清单

| 场景 | 需要证明什么 |
|---|---|
| 正常任务 | 从自然语言请求到真实数据库结果的完整链路。 |
| 意图不清 | 系统不会在缺少必要参数时直接执行错误任务。 |
| 数据异常 | 缺失行、重复记录、空值和精度问题有明确处理。 |
| 操作边界 | 不允许的操作在 Tool 执行层被拒绝，界面和 Agent 行为一致。 |
| 执行证据 | 可以核对调用参数、数据库结果、计算规则及最终解释。 |
| 部署与打包 | 在新环境启动，连接配置缺失或失效时有清楚反馈。 |

以上为工程自测建议，不是官方统一测试用例或评分门槛。无需照抄课程里测试数量和代码规模。

## 7. 建议交付物与主要难点

可准备源码与启动说明、数据库初始化脚本、Skill/Tool 契约、Agent 接入说明、验证案例、运行记录和演示材料。需要独立产品时再附相应打包产物和环境要求。

主要难点通常是数据语义、确定性执行、不同入口的一致性，以及真实可复现的结果。漂亮界面和自动生成大量代码不能代替这些工作。

正式题包需要确认：题目究竟要求使用 Qoder 完成开发、接入 SDK、实现特定工具，还是另有指定任务；同时核对必用数据库产品、允许模型、提交形态及评测方式。
