# 阶跃星辰：浏览器端向量化与 seekdb 迷你知识库

整理日期：2026-10-26  
材料：[课程 850](https://open.oceanbase.com/course/850) · [阶跃星辰官方解析视频](https://www.oceanbase.com/video/9002445)，约 16 分 46 秒

## 1. 这道题主要做什么

开发一个能导入文档、建立知识库并进行语义检索的 Web 应用。它的核心约束是：**embedding 模型在用户设备的浏览器本地运行**，seekdb 实际负责数据存储与检索。

基本流程是：

```text
文档导入 → 切分与元数据整理 → 浏览器本地生成向量
        → 向 seekdb 写入向量、原文、元数据
        → 查询向量化 → 向量与全文混合检索 → 展示命中原文
```

这道题的重点在端侧推理、数据库使用和工程优化。生成长篇聊天回答不是课程明确给出的核心任务。

## 2. 视频明确的要求

- 使用可在浏览器运行的开源 embedding 模型，核心推理不能交给云端模型 API，也不能移到服务端后伪装成端侧运行。
- 模型考虑 int8 或 fp16 量化，并说明压缩及精度变化。
- 优先使用 WebGPU；不支持时降级到 WASM，向用户说明实际运行模式。
- 使用 seekdb 存储与检索向量、原文和元数据；实现向量与全文混合检索，不能只在客户端拼接两组结果冒充数据库混合检索。
- 处理增量写入、集合/会话状态、索引刷新等工程问题，并可围绕批处理和查询延迟优化。
- 交付可运行的 Web 应用、完整源码、启动说明及一页技术说明。

视频列举 MiniLM、bge-small 等作为端侧模型参考，模型并非必须选某个阶跃大模型。“浏览器本地推理”也不等于数据库必须装在浏览器内部：课程允许嵌入式 seekdb 或附启动脚本的服务方式。

## 3. 建议的模块划分

本节为实现建议。

| 模块 | 职责 |
|---|---|
| 文档处理 | 导入、切分、去重，保留来源和文档标识。 |
| 浏览器推理 | 模型下载与缓存、加载进度、量化模型推理、WebGPU/WASM 切换。 |
| 数据访问 | 集合管理、批量写入、索引刷新及检索调用。 |
| 查询与展示 | 本地编码查询，展示命中片段、来源和可解释的状态。 |
| 运行状态 | 区分模型未就绪、写入中、索引待刷新、可检索和失败重试。 |

建议把模型推理放入 Web Worker 等独立执行单元，避免大量文档向量化时阻塞页面。具体浏览器和运行库版本需在实际环境中验证并固定。

## 4. 最小可运行版本的实现顺序

1. **先验证推理**：在目标浏览器上加载一个小型开源模型，编码短文本，确认执行发生在本地。
2. **跑通数据链路**：用一份小文档写入原文、向量和来源信息，完成首次查询。
3. **补齐混合检索**：验证语义相关词、精确术语两类查询，保存查询配置和结果。
4. **实现降级**：主动测试 WebGPU 不可用的环境，确保切到 WASM 后仍可使用，界面状态准确。
5. **处理更新**：新增文档后可以检索；重复导入、写入失败和刷新未完成时有明确行为。
6. **再做性能优化**：比较批量大小、文档切分、模型量化和索引刷新策略。

先保证一条真实链路可用，再扩展文档格式和界面功能。可选图片支持不宜成为第一阶段的主要负担。

## 5. 怎么验证

下表用于自测，不是官方评分表。

| 场景 | 需要观察什么 |
|---|---|
| 模型首次加载与再次加载 | 下载体积、加载时间、缓存是否生效。 |
| 本地推理 | 网络请求与代码路径能证明没有调用远端推理服务。 |
| 模型量化 | 与基准模型比较向量/检索质量、体积和处理速度。 |
| WebGPU 与 WASM | 两种模式均能完成同一任务，实际后端显示正确。 |
| 增量导入 | 新数据能够进入检索，失败重试不会产生失控的重复数据。 |
| 检索质量 | 用固定文档与查询集检查语义、精确词和混合检索效果。 |
| 性能 | 文档向量化吞吐、查询延迟、批量与刷新开销。 |

冷启动和热启动应分别记录。对比量化方案时保持语料、查询和检索参数一致，避免把模型变化与索引变化混在一起。

## 6. 交付清单

视频明确提到三类交付物：

1. **可运行应用**：本地可启动 Web 项目，附 seekdb 的嵌入式使用或启动方式。
2. **完整代码**：前后端源码及 README，说明安装、数据初始化和启动命令。
3. **一页技术说明**：模型来源、量化方案及效果、seekdb 使用方式、降级策略与优化点。

建议额外准备一个小型演示语料、固定查询和结果记录，使其他人能快速复现主流程；这是交付建议，不是课程新增的必交文件。

## 7. 最容易出错的地方

- 只做一个知识库页面，实际向量化仍调用远端 API。
- 数据库只保存展示数据，检索结果由前端硬拼或预先准备。
- 仅在自己的 WebGPU 环境可用，没有可工作的 WASM 降级路径。
- 文档已写入就提示可检索，实际索引尚未刷新。
- 只比较加载后查询速度，遗漏模型下载和初始化成本。

正式题包仍需确认浏览器版本、数据格式与规模、评分口径、运行环境及提交方式。
