# 离谱辩题：运行说明

## 玩法

夜班辩论俱乐部只有一条规矩：你说一句，杠精主持人必须站到对面，并且翻出以前有人说过的胡话来压你。

玩家提交辩手、辩题、立场和一段辩词。应用先从旧档案里找能抬杠的记录，再给出主持人的反驳和离谱指数，最后把这一轮写回去。下一轮可以撞上刚才说的话。

六条预置辩题在 `data/seed_arguments.json`：猫应该交税、冰箱应该有投票权、周一应该被取消、梦想可以按斤出售、雨天必须配给免费热汤。样例输入在 `data/sample_input.json`。

## 分工

| 部分 | 做什么 |
| --- | --- |
| Dify DSL `docs/absurd_debate.dsl.yml` | 编排「输入 → HTTP 检索 → 回应 → HTTP 保存 → 输出」。回应是代码节点，不调用大模型。 |
| HTTP 服务 `src/server.py` | 只监听 `127.0.0.1:18604`。检索和保存都进 seekdb。 |
| seekdb collection `track04_debate` | 存在数据库 `track04_dify`。保存辩词，并用一次 `hybrid_search` 做全文加向量检索。融合用数据库里的 RRF，Python 不自己合并两路结果。 |
| 64 维向量 | `src/hashvec.py` 用标准库哈希把文本打成单位向量，不下载模型。 |

本机没有 Dify 界面。DSL 未导入 Dify，也没有假装导入过。可玩的入口是下面的 curl。`results/sample_run.json` 是按 DSL 顺序打完的一局。

## 环境

- 代码在 `/data/zouyuanwei/oceanbase/tracks/04_dify_workflows`。
- 已有 seekdb 监听 `127.0.0.1:2881`。不要重启它，不要 docker pull，不要改其他目录。
- 连接信息在本目录权限 600 的 `.env`。不要覆盖，说明里也不写密码。
- Python 3.11，项目已锁定 `pyseekdb==1.4.0.post1` 和 `PyMySQL==1.2.3`。本题没有新增依赖。
- DSL 按 Dify 1.12+ 的 `0.5.0` 编写。导入前把环境变量 `DEBATE_API_BASE` 留在 `http://127.0.0.1:18604`。Dify 必须和这个服务在同一台机器上，因为服务不对外网卡开放。
- 辩词里不要写英文双引号。检索节点的 JSON 模板会被双引号截断。保存节点用代码节点做了 `json.dumps`，不受这个限制。

## 启动

```sh
cd /data/zouyuanwei/oceanbase
. ./env.sh
uv run --locked python tracks/04_dify_workflows/src/server.py
```

启动时会把种子辩词 upsert 进 `track04_debate`，并 `refresh_index`。另开一个终端：

```sh
curl -sS http://127.0.0.1:18604/health
curl -sS http://127.0.0.1:18604/v1/motions
```

自测和样例一局：

```sh
cd /data/zouyuanwei/oceanbase
. ./env.sh
uv run --locked python tracks/04_dify_workflows/tests/test_debate.py
uv run --locked python tracks/04_dify_workflows/src/play_round.py
```

`play_round.py` 自己拉起服务，并用 curl 依次调用 `/v1/retrieve`、`/v1/respond`、`/v1/save`，再用同样的检索确认刚写入的辩词已经能被 hybrid_search 找到。成功后服务留在 `127.0.0.1:18604`。

手工打一局时，先检索：

```sh
curl -sS http://127.0.0.1:18604/v1/retrieve \
  -H 'Content-Type: application/json' \
  --data-binary @tracks/04_dify_workflows/data/sample_input.json
```

样例文件的字段是 `argument`。检索接口接受 `text` 或 `argument`。把返回的 `hits` 和原输入交给 `/v1/respond`，再把回应交给 `/v1/save`。

## 样例里应该看到什么

夜班辩手以正方主张「猫应该交税」。检索应命中同题旧档案，而不是冰箱或周一。主持人站反方，回应里点出被引用档案的 id，并给出 1 到 99 的离谱指数。保存返回 `p_<round_id>` 和 `h_<round_id>`，且 `refreshed` 为 true。再用刚保存的辩词检索，结果里要有 `p_<round_id>`。

开放式抬杠没有唯一标准答案。同一输入必须得到同一句回应。

## 限制

- 主持人是规则，不是模型。同词会靠近，换一种说法不一定能检索到。
- 全文用 seekdb 的 IK 分词。检索词来自辩题里的内容词。
- 向量只有 64 维，只适合这个小游戏，不能当成通用语义嵌入。
- 重复发送同一辩词会 upsert 同一个 id，不会无限加行。
