# 离谱许愿池：运行说明

## 玩法

一口废弃喷泉改成的许愿池，住着一位池神。玩家投下一枚离谱愿望，池神先用 seekdb 在旧账里做一次 hybrid search，翻出三个最像的旧愿望，再写一封温柔又离谱的「回声信」：引用旧愿望、判定应验概率和离谱指数、赠送一件不存在的赠品，并盖一枚许愿币编号。最后这封信和愿望一起被投回池子，成为下一位许愿人的回声。

换一个新会话、甚至换一个陌生人许愿，旧愿望都会浮上来回响——这就是跨会话记忆的玩法核心。

## 分工

| 部分 | 做什么 |
| --- | --- |
| Dify DSL `docs/wishwell.dsl.yml` | 编排「输入 → HTTP 投币 → 池神(LLM) → 制币 → HTTP 入池 → 输出」，按 Dify 1.12+ 的 DSL `0.5.0` 编写。 |
| HTTP 服务 `src/server.py` | 只监听 `127.0.0.1:18604`。投币和入池都进 seekdb。 |
| seekdb collection `track04_wishwell` | 存在数据库 `track04_dify`。保存愿望与回声，检索用一次 `hybrid_search`，向量与全文两路由 seekdb RRF 融合，Python 不自行合并两路结果。 |
| 64 维向量 | `src/hashvec.py` 用标准库哈希把文本打成单位向量，不下载模型、不调用 Embedding 服务。 |

## 环境

- 评测机已有 seekdb 监听 `127.0.0.1:2881`。不要重启它，不要 docker pull，不要改其他目录。
- 连接信息在本目录权限 600 的 `.env` 中。不要覆盖，说明里也不写密码。
- Python 3.11+；项目锁定 `pyseekdb==1.4.0.post1` 和 `PyMySQL==1.2.3`，无其他依赖（HTTP 服务用标准库）。
- DSL 按 Dify 1.12+ 的 `0.5.0` 编写。导入前把环境变量 `WISH_API_BASE` 留在 `http://127.0.0.1:18604`。Dify 必须和这个服务在同一台机器上，因为服务不对外网卡开放。
- 本机没有 seekdb 服务时，`WISHWELL_STORE=file` 会启用一个 JSON 文件替身（`data/wishwell-store.json`），接口形状完全一致，仅用于本地体验与单测；比赛证据使用默认的 seekdb 存储。

## 启动（评测机，seekdb 模式）

```sh
cd ~/oceanbase
. ./env.sh
uv run --locked python tracks/04_dify_workflows/src/server.py
```

启动时会把预置愿望 upsert 进 `track04_wishwell` 并 `refresh_index`。另开一个终端：

```sh
curl -sS http://127.0.0.1:18604/health
curl -sS http://127.0.0.1:18604/v1/pond
```

## 自测与样例一局

```sh
cd ~/oceanbase
. ./env.sh
uv run --locked python tracks/04_dify_workflows/tests/test_wishwell.py
uv run --locked python tracks/04_dify_workflows/src/play_wish.py
```

`test_wishwell.py` 会跑单元检查与真实 seekdb 检查（hybrid 命中、写入后可检索、DSL 与运行时一致），结果写入 `results/test_report.json`。`play_wish.py` 自己拉起服务，按 DSL 的顺序打完整一局（投币 → 池神回声 → 入池 → 再投币验证能召回自己的许愿币），结果写入 `results/sample_run.json`。成功输出 `TEST_OK`，样例一局会打印回声信全文。

手工投一枚币：

```sh
curl -sS http://127.0.0.1:18604/v1/toss \
  -H 'Content-Type: application/json' \
  --data-binary @tracks/04_dify_workflows/data/sample_input.json
```

## 样例里应该看到什么

以 `data/sample_input.json` 为例（许愿人「试池的人」，愿望是让周五永不结束、食堂鸡腿每天多一根）：

1. `/v1/toss` 返回 `hits`：预置愿望里有关「放假 / 天气 / 食物」的旧涟漪，`fusion` 为 `seekdb_hybrid_rrf`。
2. 池神回声信会点名至少一条旧愿望的许愿人和内容，给出 `grant`（应验概率）与 `absurdity`（离谱指数），并附赠品与许愿币编号。
3. `/v1/keep` 返回 `w_<coin>`、`e_<coin>` 两个 id 且 `refreshed` 为 true。
4. 用相近句子再投一次币，结果里能找回自己那枚许愿币——这证明 seekdb 的写入与 hybrid 检索在应用功能中真实生效。

同一输入必须得到同一句回声（池神在无模型环境下的确定性替身由 `src/poolgod.py` 保证；接入模型后回声内容由模型生成，结构不变）。

## 在 Dify 里体验

1. 导入 `docs/wishwell.dsl.yml`（Dify 1.12+，DSL 0.5.0）；本机是 Dify 1.9.x 时改用 `docs/wishwell-dify-1.9.x.yml`（0.3.1 变体，`python scripts/build_local_variant.py` 可重新生成）。
2. 在「池神」LLM 节点绑定一个可用的 Chat 模型。
3. 确认两个 HTTP Request 节点地址指向 `http://127.0.0.1:18604`（Dify 与服务同机）。
4. 运行：许愿人可留空，愿望写 `周五永远不结束，食堂鸡腿每天多一根`。
5. 换新对话再许一个相近的愿望，池神会引用上一轮的旧愿望。

## 限制

- 池神的文学质量取决于绑定的模型；无模型环境下 `poolgod.py` 提供确定性回声，保证流程可验收。
- 向量只有 64 维，是给这个小游戏用的特征哈希，不是通用语义嵌入；换一种说法可能检索不到，全文腿用 seekdb 的 IK 分词补足。
- 重复投同一愿望会 upsert 同一个 id（按 `player|wish` 哈希），不会无限加行。
- 愿望里不要写英文双引号之外的敏感内容；本应用只适合放虚构、无害的愿望。
